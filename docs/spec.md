# 風除室DXF生成Webアプリ 仕様書（完成版・実務拡張仕様含む）

手書きや画像ベースの「風除室（ふうじょしつ）」の図面を外部AI（ChatGPT等）で解析して得た図面JSONを読み込み、ブラウザ上でのプレビュー表示、およびCADで直接編集可能なDXFファイルの生成・ダウンロードを行うWebアプリケーションの仕様書です。

## 1. プロジェクト概要

### 1.1 システムの狙い

建物の出入り口付近に設置される「風除室」の平面図を想定し、高価なAI APIのランニングコストを抑えつつ、ユーザーの「手書きスケッチ ➔ CAD化」のプロセスを極限まで効率化する。

### 1.2 アプローチの特徴

- **AI APIの非連携（ローコスト運用）:** 画像の読み取りと構造化データ（JSON）への変換は、ユーザーが普段使っているChatGPT等の外部AIに依頼する。

- **完全フロントエンド完結（サーバーレス）:** Node.js/Python等のサーバーサイド処理を介さず、ブラウザのJavaScriptのみで図面プレビュー（SVG描画）およびCAD互換形式（アスキーDXFテキスト）の即時生成とBlobダウンロードを実現する。

## 2. ターゲットユーザーとユースケース

### 2.1 対象ユーザー

- サッシ工事店、外構エクステリア施工業者、リフォーム会社の現場担当者

- 現場の採寸メモや手書きスケッチを預かり、CAD（Jw_cad, LibreCAD, AutoCADなど）で素早く下書き図面を起こしたい設計アシスタント

### 2.2 エンドツーエンドの利用フロー

1.  **現地採寸・手書きメモ作成:** 現場にて風除室の採寸を行い、手書き平面図やスケッチ（土間寸法、または風除室完成図）を作成する。

2.  **外部AIによる解析:** 手書き図面をスマホで撮影し、ChatGPT等にアップロード。本アプリが提供する「AI指示プロンプト（用途に合わせて2種類から選択）」を添えて図面JSONの生成を指示する。

3.  **JSONデータの取り込み:** AIが生成したJSONデータを本アプリの「JSONデータ入力」エディタにペーストする（または .json ファイルとしてアップロード）。

4.  **自動バリデーションとプレビュー:** 貼り付けと同時にリアルタイムで構文チェックと構造バリデーションが走り、画面右側の大型プレビューエリア（SVG）に図面が表示される。ユーザーはズームや移動で誤りがないか目視確認する。

5.  **DXF保存:** 「DXF保存」ボタンをクリックし、ミリメートル（mm）実寸スケール・レイヤー分けされたDXFファイルをダウンロードする。

6.  **CADでのクリンナップ:** ダウンロードしたDXFファイルを使い慣れたCADソフトで開き、建物の詳細線などを書き足して最終図面を仕上げる。

## 5. 図面JSONスキーマ仕様

AIに指示を出すためのJSONは、風除室特有の構造に特化し、ミリメートル（mm）単位の平面X-Y座標系で統一します。

### 5.1 スケールと座標定義

- **単位:** mm

- **X軸:** 右方向が正の数

- **Y軸:** 上方向が正の数（※SVG描画時は上方向が負となるため、React内部で y の数値を -y としてプロットする）

### 5.2 JSONデータプロパティ要件

| **親キー**    | **サブプロパティ** | **型** | **役割・制約**                                               |
|---------------|--------------------|--------|--------------------------------------------------------------|
| version       | \-                 | string | スキーマバージョン（仮定: "1.0"）                            |
| unit          | \-                 | string | 単位。"mm" 固定                                              |
| drawingBounds | min, max           | object | 図面描画領域の対角座標（X, Y）。SVGの viewBox 計算に直接使用 |
| layers        | 各種配列要素       | object | 図面を構成するレイヤー（以下詳細）                           |

#### layers 内の構成要素

1.  **existingBuildingLines (既存建物ライン)**

    - 既存壁や玄関枠。CADの EXISTING_BUILDING レイヤーに変換。

    - プロパティ: id (string), start (Point), end (Point), lineType ("solid" \| "dashed" \| "dotted")

2.  **vestibuleOutline (風除室外形線)**

    - 風除室設置予定の骨組みライン。

    - プロパティ: id (string), points (Point\[\]), closed (boolean)

3.  **frames (サッシ枠)**

    - アルミ形材。DXF上で厚みのある実線で描画。

    - プロパティ: id (string), start (Point), end (Point), thickness (number), material (string:任意)

4.  **posts (柱部材)**

    - コーナー柱や中間柱。正方形または長方形ブロック。

    - プロパティ: id (string), position (Point:中心点), width (number), depth (number)

5.  **mullions (方立/縦補助枠)**

    - サッシ内に細かく入る縦枠。

    - プロパティ: id (string), start (Point), end (Point), thickness (number)

6.  **glassPanels (ガラス面)**

    - ガラスの位置。

    - プロパティ: id (string), points (Point\[\]), glassType (string)

7.  **slidingDoors (引き戸シンボル)**

    - 2枚引違い、片引き等の引き戸平面記号（二重線のズレと開口方向矢印）。

    - プロパティ: id (string), start (Point), end (Point), width (number), direction ("left" \| "right" \| "both"), panelCount (number)

8.  **hingedDoors (開き戸シンボル)**

    - ドア本体 durable な線と、90度の開閉軌跡円弧。

    - プロパティ: id (string), position (Point:吊元位置), width (number:扉幅), angle (number:開き角度), swing ("inward" \| "outward")

9.  **fixedWindows (FIX窓)**

    - はめ殺し窓。

    - プロパティ: id (string), start (Point), end (Point), width (number)

10. **dimensions (寸法線)**

    - 寸法値、寸法線、引き出し線の集合。CAD互換性を高めるため、DXF出力時は基本図形の組み合わせ（分解寸法）に展開する。

    - プロパティ: id (string), start (Point), end (Point), text (string), offset (number:寸法線までの逃げ距離)

11. **labels (部材ラベル) / notes (注記テキスト)**

    - プロパティ: id (string), text (string), position (Point), height (number:文字高)

12. **directionMarker (正面方向/方位表示)**

    - プロ放物: id (string), position (Point), direction (number:角度), label (string)

## 8. 風除室の実務に特化した設計・要検討拡張仕様

本セクションは、単なる2Dデータ変換を超え、実際のサッシ組み立て・現調（現場調査）・施工段階におけるトラブルを防ぎ、プロが実務で活用できる図面を書き出すための極めて重要な仕様検討事項です。

### 8.1 既存壁面との取り合い（アタッチメント・チリ・シール逃げ）

- **課題:** 風除室のアルミ外枠（フレーム）を既存の外壁（RC、サイディング、凹凸のあるタイル等）に直にビス留めする場合、壁面の凹凸による歪みや雨水浸入を防ぐ「コーキング（シーリング）幅」が必要です。また、サイディングのジョイント部を避けるために「ふかし枠（アタッチメント）」を噛ませることが多々あります。

- **仕様（案）:** \* JSONの frames に wallClearance: number (ミリ) 属性を追加。

  - 例えば wallClearance: 15 が指定されている場合、アプリはプレビュー上およびDXF上で既存壁線から15mm意図的に離した位置に外枠線（フレーム）を描き、その隙間に **「シーリング（コーキング）充填スペース」** として破線、または寸法引出線を自動描画する。

  - 既存壁との接点（両端）に自動で「アタッチメント役物枠（L字アングル）」を示す矩形を自動生成する。

### 8.2 床面のレベル差（水勾配・ポーチ段差）への配慮

- **課題:** 多くの住宅ポーチには、雨水が建物内へ逆流しないよう **「水勾配（1/50〜1/100程度の傾斜）」** がついています。また、階段ステップ（段差）の角ギリギリに風除室の柱を立てるケースや、ステップを跨いで下レールを浮かせるケース（ハンガー引戸仕様）があります。

- **仕様（案）:**

  - 平面図上に段差位置を表す「床段差ライン（境界線）」を existingBuildingLines や、新規に floorLevels レイヤーを追加して表現する。

  - JSON内に floorLevels 配列を設け、各エリアごとの基準レベル（例：{"id": "fl1", "label": "FL±0 (ポーチ面)", "level": 0}, {"id": "fl2", "label": "FL-150 (ステップ下面)", "level": -150}）をプロットし、高低差を示す平面指示マークを出力する。

### 8.3 引き戸の「召し合わせ（重なり）厚」と「有効開口幅」の自動算出

- **課題:** 風除室の2枚引き違い引戸などにおいて、全体の枠幅（例えばW=3000）を均等に半分にして2枚の扉を配置しても、中央の重なり部分（召し合わせ部）があるため、実際の通行幅（有効開口幅）は枠の半分（1500mm）より必ず狭くなります（サッシ見込み・引き残しにより通常100mm前後減少する）。

- **仕様（案）:**

  - 平面図上に引き違い戸を描く際、中央の召し合わせ部を精密に「重なりを持った二重長方形」として描画する。

  - ユーザーおよびサッシ組み立て業者が一目で有効な通路幅を把握できるよう、「有効開口幅（Clear Opening Width）」の補助寸法線を、実計算の上で自動描画（例：W=1200に対して「有効W=1085」など）する。

### 8.4 屋根（庇の出幅）ラインと雨樋・換気ランマ

- **課題:** 風除室には必ず天井（屋根ガラスまたはアルポリック板）が設置されます。正面サッシ枠よりも前方に「庇（ひさし）」が100〜150mm程度突き出すのが一般的であり、その先端に雨樋が付きます。また、夏場の室温急上昇を防ぐ「換気用の可動式ランマ窓（または網戸付）」が必要不可欠です。

- **仕様（案）:**

  - 庇の投影ライン（境界線）を ROOF_OVERHANG レイヤー（推奨色：マゼンタ・線種：DASHED）として追加。

  - 平面図サッシの手前側に、飛び出し幅（例：overhang: 150）に応じた破線を自動出力する。

  - 雨樋（たて樋）が落とされる位置（通常は左右 of コーナー柱付近）に、丸記号「φ」や「○」による雨樋プロット記号を描画する。

### 8.5 CAD側のスケール（縮尺）と文字高さの整合性（★特に重要）

- **課題:** AutoCADやLibreCADは「モデル空間（実寸1:1）」で描いた図面を印刷時にレイアウト枠で縮尺をかけますが、**日本の現場サッシ業界で主流の「Jw_cad」は、図面グループ（レイヤ）ごとに縮尺（例：S=1/20）を最初に固定して作図する文化**があります。

  - 実寸1:1のDXFテキスト（文字高さ50mm等）をJw_cadで開いた際、Jw_cad側のレイヤが「1/20」に設定されていると、文字サイズが20倍の「1000mm（1メートル！）」に誤認されて図面が文字で埋め尽くされ、壊れる現象が発生します。

- **仕様（案）:**

  - DXFエクスポート画面に **「出力CADスケール（縮尺）の選択」**（1/1, 1/10, 1/20, 1/50等）を設定するトグル、またはセレクトボックスを用意する。

  - CADスケールが「1/20」に指定された場合、DXFの TEXT 要素を出力する際に、実サイズ50mmの文字を出力パラメータ上「50 / 20 = 2.5mm（Jw_cad上の文字サイズ表現）」などへスケーリング計算をして書き出す、高精度Jw_cad互換変換モードを搭載する。

### 8.6 AI（ChatGPT）の寸法誤差をアプリ側で吸収する「自動クランプ（補正）ロジック」

- **課題:** AI（ChatGPT）が画像を読み取ってJSONを作る際、「全体幅が3000、左FIX窓が900、引き戸が1200、右FIX窓が900」と出力しても、フレームの厚み（70mm×サッシ数）が足し算から漏れており、幾何学的に端点が合わずにプレビュー線が隙間だらけになったり、飛び出したりする「足し算の矛盾（ゆらぎ）」が極めて高い確率で発生します。

- **仕様（案）:**

  - **「枠優先クランプ（外枠優先自動結合）」** のフロントエンドアルゴリズムを実装する。

  - ユーザーが入力した個別のサッシ幅の合計が外郭寸法とズレている場合、外枠 vestibuleOutline およびコーナー柱 posts の配置を絶対的な境界（アンカー）とし、その内側に収まるようにFIX窓や引戸の start / end 座標をアルミフレーム of 厚み thickness を引いた上で自動接続（スナップ）して補正再計算するモジュールをプレビュー描画前段に組み込む。

## 9. AI指示用プロンプト仕様（用途別2種類）

本アプリに静的に組み込む「AI指示プロンプト」の具体的なコンテンツ定義です。ユーザーの入力元データの状態に合わせ、最も高精度な図面JSONを生成できるようにパラメータ計算ロジックをプロンプト内に構造化しています。

### 9.1 プロンプトA：土間・既存壁寸法図面から風除室を設計・生成させる場合

土間ポーチや既存壁の採寸メモから、風除室の構成部材位置をAI側で自動計算してJSON化させるためのプロンプトです。

\# 命令  
あなたは優秀なサッシおよび外構（エクステリア）の図面作成アシスタントです。  
提示された「土間（ポーチ）や既存壁の寸法が描かれた平面図・採寸メモ」の画像を極めて精密に解析し、以下の【設計ルール】に従って計算・設計した、風除室（ふうじょしつ）の平面図JSONのみを出力してください。  
マークダウン箇所（前後の日本語の挨拶、説明等）は一切不要です。純粋なJSONのみを返してください。  
  
\# 単位  
- すべてミリメートル（mm）単位とします。  
  
\# 設計ルール（土間・壁からの逆算）  
1. 【風除室外郭（vestibuleOutline）の決定】:  
- 風除室は、土間の端（境界ライン）より一律 50mm 内側（オフセット）に設置するものと仮定し、外郭座標を決定してください。  
2. 【既存壁との結合（existingBuildingLines）】:  
- 既存の建物壁面および玄関枠のラインを正確に抽出し、風除室が突き当たる位置に直線を配置してください。  
3. 【柱（posts）の自動配置】:  
- 外郭の出隅（コーナー角）の内側に、90mm x 90mm のアルミコーナー柱を自動で配置してください（postsレイヤーに中心座標・幅・奥行きを指定）。  
4. 【建具・FIXの配置割り出し】:  
- 正面（土間先端）の間口寸法に基づき、中央部に「幅1200mmの2枚引き違い引き戸（slidingDoors）」を配置し、残った左右の隙間に「FIX窓（fixedWindows）」を等幅で自動配置してください。  
- アルミフレーム（frames）の標準見込み（厚み）は 70mm とします。  
5. 【寸法線（dimensions）】:  
- 土間の外寸、および風除室の仕上がり外寸、引き戸開口幅を示す寸法線を自動算出してプロットしてください。

### 9.2 プロンプトB：手書きの風除室平面図・完成ラフから直接トレース生成させる場合

ユーザーがすでに「風除室そのものの完成予想平面図」を寸法入りで描いている場合に、それを忠実にJSON座標へマッピングさせるプロンプトです。

\# 命令  
あなたは優秀なサッシおよび外構（エクステリア）の図面作成アシスタントです。  
提示された「手書きの風除室完成平面図・ラフスケッチ（寸法入り）」の画像を極めて精密に解析し、描かれている風除室の形状、柱位置、ドア種類、ガラス、寸法情報をすべて抽出し、以下の【JSON Schema】に完全に適合する平面図JSONのみを出力してください。  
マークダウン箇所（前後の日本語の挨拶、説明等）は一切不要です。純粋なJSONのみを返してください。  
  
\# 単位  
- すべてミリメートル（mm）単位とします。  
  
\# 抽出ルール（忠実なトレース）  
1. 【外壁・既存物（existingBuildingLines）】:  
- スケッチに記述された「既存サッシ枠」「既存建物壁（タイル面等）」を識別し、実座標にマッピングして直線を描画してください。  
2. 【サッシ枠・柱の抽出（frames / posts）】:  
- スケッチ上に描かれた枠線およびコーナー柱（「柱」「90角」などのメモがある部分）を検出し、その座標とサイズ（幅・奥行）を忠実に変換してください。  
3. 【ドアの開閉方式の識別（slidingDoors / hingedDoors）】:  
- 「引違い戸」「片引き戸」「開き戸（スイング）」を記号から正確に分類し、適切な平面記号配列に代入してください。  
4. 【寸法値・注記（dimensions / notes）】:  
- スケッチ内に手書きで引き出されている「W=3000」「D=1500」などの寸法線と、余白に書かれている現場の注意書きメモ（例：「土間ハツリ要す」など）をテキストとして余さずJSONに格納してください。  
  
\# JSON Schema:  
※プロンプトAで指定されたスキーマと同一形式で、抽出した風除室データを格納して出力すること。

*仕様書 完.*
